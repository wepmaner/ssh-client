# Доступ Claude к серверам через MCP

Дата: 2026-10-31.

## Зачем

Владелец часто даёт Claude доступ к серверу, и это ломается: Claude не может войти по ключу с парольной фразой, а сведения о сервере (нестандартный порт, какой ключ, какой пользователь) лежат в памяти того проекта, для которого сервер брался. Последний случай: другому проекту понадобился сервер, порт 22 закрыт, ключ от root неизвестно где, и данные пришлось вытаскивать через первый проект. Сейчас Claude подключается напрямую, в обход клиента.

В клиенте уже есть всё нужное: адреса, порты, пользователи, ключи и единый вход с фразой. Он становится посредником для любой сессии Claude на этом компьютере.

Успех: владелец один раз включает тумблер и один раз добавляет сервер в Claude Code. После этого Claude в любом проекте видит открытые хосты, смотрит состояние сервера и контейнеров, запускает и останавливает их, заливает и скачивает файлы. Ключ и фразу он не получает никогда, фразу один раз вводит владелец в окне клиента.

## Решения владельца (2026-10-31)

1. MCP встроен в клиент и включается тумблером.
2. Основной сценарий: смотреть состояние, запускать и останавливать Docker-контейнеры, заливать и скачивать файлы. Значит, нужна и запись.
3. Подтверждений команд нет: Claude работает без остановок («я верю ему»).
4. Режим «только чтение» нужен там, где возможен. Владелец знает, что это защита от случайностей, а не строгая гарантия. Настоящее ограничение даёт только отдельный пользователь с малыми правами на сервере.
5. Клиент даёт готовый промпт для копирования, с которым Claude сам подключает MCP.

## Цели

- Локальный MCP-сервер внутри `sshclient.exe`, включается тумблером в Настройках.
- У каждого хоста режим доступа: закрыт, только просмотр или полный.
- Инструменты: список хостов, выполнение команды, заливка файла, скачивание файла.
- Вход идёт через общее подключение хоста. Если нужен ввод, клиент показывает окно.
- Журнал действий Claude в клиенте.

## Не цели

- Интерактивные команды и псевдотерминал (`top`, `vim`, `sudo` с запросом пароля).
- Файловый менеджер в интерфейсе и передача папок: Claude упакует папку через `tar`.
- Подтверждение команд.
- Подключение к MCP с другого компьютера.
- Настройка MCP других программ: команда подключения рассчитана на Claude Code. Сервер работает по стандартному протоколу, поэтому другие клиенты могут подключиться вручную.
- Отдельная автоматическая настройка пользователя на сервере.

## Анти-цели (провал, даже если работает)

- Приватный ключ, парольная фраза, пароль входа или токен MCP попадают в ответ инструмента, журнал, событие или лог.
- MCP принимает запрос без верного токена или слушает не только `127.0.0.1`.
- Закрытый хост виден Claude или доступен ему.
- Тумблер выключен, а порт открыт.
- Клиент запрашивает фразу на каждую команду, пока подключение открыто.
- Работа MCP рвёт консоли и пробросы хоста.
- Изменившийся ключ сервера принимается. Окно доверия неизвестному серверу работает как обычно: только владелец может подтвердить ключ, у Claude такого инструмента нет.

## Известные ограничения

- При полном доступе Claude может всё, что может пользователь хоста на сервере, и прочитать там любые секреты. Текст об этом показывается при выборе режима.
- Режим «Только просмотр» тоже показывает всё, что читаемо этому пользователю, например `docker inspect` с переменными окружения и файлы с паролями.
- Вывод команд с сервера попадает в Claude и может содержать вредоносные инструкции. Владелец принял этот риск, отказавшись от подтверждений.
- Если подключение оборвалось, например после `reboot`, и пробросов на хосте нет, секреты зачищаются по существующему правилу: следующая команда снова запросит фразу.
- Закрытие хоста и выключение тумблера не являются аварийной остановкой: процесс на сервере может продолжить работу, потому что SSH без псевдотерминала не гарантирует его завершения.
- Автоблокировка считает только активность в окне. Работа Claude её не откладывает.

## Поведение

### Раздел «MCP»

Отдельный раздел «MCP» в боковой панели, между «Пробросы» и «Настройки» (решение владельца, 2026-10-31, вместо блока в Настройках). Тексты интерфейса не называют Claude (решение владельца, 2026-10-31):

- тумблер «Разрешить доступ к серверам по MCP», по умолчанию выключен;
- поле «Порт», по умолчанию `47821`. Порт постоянный, потому что он записан в настройках Claude Code; при смене порта команду подключения нужно выполнить заново;
- кнопка «Скопировать команду подключения»:
  `claude mcp add --transport http --scope user sshclient http://127.0.0.1:<порт>/mcp --header "Authorization: Bearer <токен>"`
- кнопка «Скопировать промпт» и рядом сам текст промпта, чтобы было видно, что копируется (решение владельца, 2026-10-31): готовый текст, который владелец вставляет в сессию нейронки, а та сама подключает сервер (решение владельца, 2026-10-31). Текст собирается из текущих порта и токена:

  ```text
  Подключи MCP-сервер SSH-клиента sshclient. Он работает на этом компьютере и даёт доступ к моим серверам.

  1. Выполни команду:
  claude mcp add --transport http --scope user sshclient http://127.0.0.1:<порт>/mcp --header "Authorization: Bearer <токен>"
  2. Скажи мне перезапустить сессию, если новые инструменты не появились сразу.

  Инструменты: list_hosts показывает доступные серверы, run_command выполняет команду, upload_file и download_file передают файлы.

  Для серверов используй эти инструменты, а не прямой ssh: ключи и парольные фразы хранит клиент, они тебе не нужны. Если клиент попросит вход, скажи мне ответить в его окне и повтори команду. Если сервера нет в list_hosts, его нужно открыть в клиенте: раздел «MCP». Токен никуда не записывай и не показывай, кроме этой команды.
  ```

- кнопка «Сменить токен»: старый сразу перестаёт работать, и команду или промпт нужно выполнить заново;
- кнопка «Журнал»;
- строка состояния: «Выключен», «Работает» или ошибка, например «Порт 47821 занят другой программой», с системным текстом в подробностях.

Токен: 32 байта из `crypto/rand`, хранится в хранилище, создаётся при первом включении. В лог не выводится; на экране виден только внутри текста промпта, отдаётся через копирование команды и промпта. Обе кнопки неактивны, пока тумблер выключен.

### Режим доступа хоста

Поле в диалоге хоста, «Доступ по MCP», и тот же выбор в списке всех хостов раздела «MCP» (решение владельца, 2026-10-31): «Закрыт» (значение по умолчанию и для всех существующих хостов), «Только просмотр», «Полный». Смена режима не требует нового входа и не трогает консоли и пробросы хоста.

- Хост стал закрытым: выполняющиеся команды и передачи MCP отменяются, удержание сразу снимается. Если других пользователей у подключения нет, оно закрывается и секреты зачищаются; при новом открытии хоста фраза спрашивается заново.
- Полный доступ сменился на «Только просмотр»: выполняющиеся вызовы завершаются, новый режим действует со следующего вызова.

Новый хост и импортированный хост всегда закрыты. Команды MCP не могут менять режим.

### Сервер

- Слушает только `127.0.0.1`, протокол MCP Streamable HTTP, путь `/mcp`, официальный `github.com/modelcontextprotocol/go-sdk`.
- Каждый запрос проходит проверку `Authorization: Bearer` сравнением постоянного времени. Запрос с чужим заголовком `Host` или с заголовком `Origin` отклоняется (защита от атак через браузер).
- Запускается при включении тумблера или после открытия хранилища, если тумблер уже включён. Хранилище с паролем до разблокировки при старте закрыто: токен неизвестен, сервер не запущен.
- После автоблокировки сервер продолжает работать, токен остаётся в памяти процесса, а новые вызовы получают ошибку «Клиент заблокирован: разблокируйте его». Выполняющиеся команды доводятся до конца.
- Выключение тумблера, выход из приложения и восстановление из копии закрывают порт, отменяют команды и передачи, отпускают подключения.

### Инструменты

Хост задаётся идентификатором или точным названием; если название неоднозначно, возвращается ошибка со списком идентификаторов. Закрытый хост отвечает так же, как несуществующий. Ошибки понятны по-русски и говорят, что делать.

| Инструмент | Параметры | Ответ |
|---|---|---|
| `list_hosts` | нет | идентификатор, название, группа, адрес, порт, пользователь, режим; только незакрытые хосты |
| `run_command` | `host`, `command`, `timeout_sec` (по умолчанию 60, максимум 600) | `stdout`, `stderr`, `exit_code`, `truncated`, `timed_out` |
| `upload_file` | `host`, `local_path`, `remote_path`, `overwrite` (по умолчанию false) | размер |
| `download_file` | `host`, `remote_path`, `local_path`, `overwrite` (по умолчанию false) | размер |

Команда выполняется в отдельном канале SSH без псевдотерминала. От каждого потока возвращаются последние 200 КБ, `truncated` сообщает об обрезке. По истечении времени или при отмене вызова клиент отправляет сигнал завершения, ждёт 2 секунды и закрывает канал, а частичный вывод возвращается. Это отмена без гарантии, поэтому ответ с `timed_out` прямо говорит Claude: команда может ещё выполняться на сервере, проверьте это перед повтором.

Файлы передаются по SFTP (`github.com/pkg/sftp`) через то же подключение, по одному файлу. Если подсистема SFTP на сервере выключена, возвращается понятная ошибка. Локальный путь абсолютный. Существующий файл без `overwrite` не перезаписывается, запись идёт во временный файл рядом и завершается переименованием. Папка данных приложения (`%APPDATA%\sshclient`) недоступна для заливки и скачивания в обе стороны, чтобы Claude не мог выгрузить хранилище. Таймаут передачи: 30 минут.

### Только просмотр

`upload_file` запрещён. `download_file` разрешён. `run_command` выполняет только то, что прошло проверку на стороне клиента, отказ объясняет, что режим хоста «Только просмотр», и команда на сервер не уходит.

Проверка своим разбором строки, запрещающий по умолчанию:

- разрешён только конвейер `|`; запрещены вне и внутри двойных кавычек `$`, обратная кавычка; вне кавычек запрещены `;`, `&`, `>`, `<`, `(`, `)`, `\`, перевод строки; незакрытая кавычка запрещена;
- каждое звено конвейера начинается с команды из списка:
  - без ограничений: `ls`, `cat`, `head`, `tail`, `grep`, `wc`, `stat`, `df`, `du`, `free`, `uptime`, `uname`, `whoami`, `id`, `ps`;
  - без аргументов: `date`; `hostname` только без аргументов или с `-f`, `-I`;
  - `ss` без `-K` и `--kill`, в том числе внутри слитных ключей;
  - `ip addr`, `ip route`, `ip link`, только чтение: без подкоманд или с `show`;
  - `systemctl` только `status`, `is-active`, `is-enabled`, `list-units`, `show`;
  - `journalctl` без `--rotate`, `--vacuum-*`, `--flush`, `--sync`, `--relinquish-var`, `--smart-relinquish-var`, `--setup-keys`, `--update-catalog`;
  - `docker` только `ps`, `logs`, `inspect`, `stats`, `images`, `version`, `info`; `docker compose` только `ps`, `logs`.
- Всё остальное отказ. Список закрепляется таблицей тестов, включая обходы: `docker ps; rm -rf /`, `cat $(reboot)`, `ls > x`, `date -s`, `hostname evil`, `ss -tK`.

### Вход

Вход выполняет существующее подключение хоста (`hostConn`). Если подключение уже открыто, команда садится на него без вопросов.

- MCP становится новым видом пользователя подключения: для хоста держится один объект-удержание. Он живёт 30 минут после последнего вызова, чтобы фраза не спрашивалась на каждую команду, затем уходит. Если он был последним пользователем, подключение закрывается и секреты зачищаются обычным образом.
- Если нужен ввод, клиент поднимает своё окно на передний план и показывает диалог «Вход по MCP: <хост>» с мини-терминалом (`forwards/MiniTerminal.svelte`). Ввод, как в консоли, с тремя попытками. Диалоги разных хостов идут по очереди. Закрытие диалога отменяет вход.
- Окно доверия ключу сервера: то же окно, что всегда; для него появляется третий владелец вопроса. Отказ возвращается Claude как ошибка.
- Если ввод идёт дольше 2 минут, вызов возвращает ошибку «Ожидается вход в окне клиента, повторите команду». Диалог остаётся, вход продолжается, повторный вызов садится на него.
- Вход, начатый консолью или пробросом, вызов просто ждёт. Изменившийся ключ сервера блокирует хост и для MCP.
- После правки адреса, порта, пользователя или ключа хоста каждый новый вызов идёт только на текущее подключение с новыми параметрами, никогда на старое: иначе команда могла бы попасть не на тот сервер, который показывает `list_hosts`. Выполняющиеся вызовы завершаются на старом подключении, пока они идут, оно их держит. Поэтому пользователем подключения считается и каждый выполняющийся вызов, а не только удержание.
- Удержание видно на подключении как обычный пользователь: `Остановить все` в разделе «Пробросы» его не трогает.

### Журнал

Каждое действие записывается до выполнения: время, хост, инструмент, текст команды или пути, режим хоста, отказ. После завершения добавляются код выхода и длительность. Вывод команд не хранится.

Журнал лежит в хранилище, потому что команды могут содержать секреты, переданные в аргументах. Хранятся последние 500 записей, текст команды обрезается до 2 КБ. В резервную копию журнал не входит. Если запись в хранилище не удалась, действие не выполняется. Если хранилище заблокировали во время выполнения, код выхода не записывается.

Диалог журнала: список от новых к старым, название хоста, поиск не нужен, кнопка «Очистить».

## Модель данных

- `model.Host`: `MCPAccess string` с `json:"mcp_access,omitempty"`, значения `""` (закрыт), `read`, `full`. `paramsOf` не меняется: режим не влияет на параметры входа.
- `model.Settings`: `MCPEnabled bool`, `MCPPort int`, `MCPToken string`. `SaveSettings` проверяет порт 1024–65535 и сохраняет токен как есть из хранилища, как `Window`; токен наружу отдаётся только методом копирования команды, и `GetSettings` возвращает его пустым.
- `model.VaultData`: `MCPJournal []model.MCPRecord`. Резервная копия его очищает, токен и настройки входят как есть.
- Старое хранилище открывается без изменений, все хосты закрыты, тумблер выключен.

## Ограничения

- Правила CLAUDE.md: фронтенд только через `frontend/src/lib/api.ts`, биндинги генерируются и коммитятся, тексты по-русски, никаких спиннеров на локальных действиях, фокус по `tokens.css`, `crypto/rand` для токена, секреты в `[]byte` с затиранием.
- Новые зависимости: `github.com/modelcontextprotocol/go-sdk`, `github.com/pkg/sftp`. Обе чисто на Go, сборка и `go test -race` на CI не меняются.
- Код MCP живёт отдельным пакетом `internal/mcpserver` с проверкой команд и обработчиками, зависящими от маленького интерфейса; `app` реализует этот интерфейс. Тесты через `sshtest`, в него нужно добавить `exec` с раздельными потоками и код выхода, если их ещё нет, и подсистему SFTP.
- CLAUDE.md обновляется: новый раздел решения, правка «вне v1» про SFTP (SFTP только как инструмент MCP), `Settings`-блок.
