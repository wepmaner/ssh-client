# SSH-клиент для Windows

Лёгкий настольный SSH-клиент под Windows 11. Цель: ощущаться как нативное, быстрое и стильное приложение, а не как веб-страница в обёртке.

## Стек (решено 2026-10-24)

- **Логика:** Go.
  - SSH: `golang.org/x/crypto/ssh` (+ `knownhosts`). Пробросы L/R/D через каналы ssh.
  - Хранение ключей: Windows Credential Manager (`github.com/danieljoos/wincred`) или DPAPI (`golang.org/x/sys/windows`).
  - Импорт .ppk: `github.com/kayrus/putty`.
- **Оболочка:** Wails v3 (`v3.0.0-beta.25`, как в Stash; решение 2026-10-25, переход с v2 сделан задачей 13a). Go + системный WebView2, один процесс, без встроенного Chromium. `App` — единственный сервис (`application.NewService`), биндинги генерирует `wails3 generate bindings -clean=true -ts` в `frontend/bindings/` (коммитятся), рантайм `@wailsio/runtime` той же версии; фронтенд ходит к ним только через `frontend/src/lib/api.ts`. Безрамочное окно с собственным заголовком и зоной перетаскивания; `UseVisualHosting: true` и обход бага DPI после восстановления окна из Stash (`app/restorefix_windows.go`). Причины перехода: системные контекстные меню (опробованы и отклонены владельцем, см. «Правила нативного поведения»), события окна и HWND, единая со Stash сборка.
- **Терминал:** xterm.js с WebGL-рендером во фронтенде; данные pty идут через события Wails.
- **Не используем:** Electron (тяжёлый), Fyne/Gio (не выглядят нативно на Windows, терминал пришлось бы писать с нуля).

## Решения по продукту

- Пароли не храним и не спрашиваем в формах: сервер спросит, пользователь введёт в консоли. То же с парольной фразой ключа. Исключение (решение 2026-10-25): доверие неизвестному ключу сервера подтверждается собственным окном приложения с отпечатком (как в PuTTY), а не вопросом в консоли; изменившийся ключ всё равно всегда отклоняется.
- Приватный ключ для хоста берётся либо из хранилища приложения (раздел «Ключи»), либо импортируется при создании хоста (файл или вставка текста). Имя импортированного ключа берётся из имени файла, переименование в разделе «Ключи».
- **Парольная фраза ключа никогда не снимается и не сохраняется (решение 2026-10-24).** Импортированный ключ хранится в исходных байтах и исходном формате (OpenSSH, PEM или PPK) вместе со своей фразой; при импорте фраза не спрашивается, публичный ключ, отпечаток и комментарий берутся из открытой части контейнера (только у старого зашифрованного PEM открытой части нет, там фраза спрашивается один раз для чтения публичного ключа и не сохраняется). Фразу спрашивает консоль при каждом подключении (до трёх попыток). Исключение для пробросов (решение 2026-10-25, задача 13c): принятую сервером фразу проброс держит только в памяти процесса, пока он запущен, и не спрашивает её при автоматических переподключениях; при остановке или удалении проброса и при выходе из приложения буфер зачищается, на диск фраза не попадает никогда. При создании ключа в приложении фразу можно задать по желанию. Экспорт зашифрованного ключа только в исходном формате, без конвертации; незашифрованный можно экспортировать в OpenSSH или PPK. Шифрование хранилища остаётся вторым, независимым слоем.
- ssh-agent не поддерживаем.
- Ключи генерируются только через `crypto/rand` (системный CNG). Сбора энтропии от пользователя (движения мыши) нет. `math/rand` в коде, связанном с ключами и шифрованием, запрещён; проверяется gosec.
- Раздел «Ключи»: создать ключ (Ed25519 по умолчанию, RSA 4096 для старых серверов; имя, тип, комментарий; парольная фраза по желанию) или импортировать файл (OpenSSH, PEM, PuTTY .ppk) без запроса фразы. Экспорт незашифрованного приватного ключа в OpenSSH и .ppk; зашифрованного — только исходный файл.
- **Хранилище:** ключи, хосты и пробросы лежат в одном зашифрованном хранилище приложения. По умолчанию защита через DPAPI (учётная запись Windows). Пользователь может включить пароль: тогда из пароля через Argon2id с случайной солью выводится ключ-обёртка (KEK), им шифруется случайный мастер-ключ (DEK), а данные шифруются DEK через AES-256-GCM или XChaCha20-Poly1305. Смена пароля перешифровывает только DEK. Пароль спрашивается при запуске; опционально разблокировка через Windows Hello (DEK хранится в Credential Manager под защитой Hello). Пароль не восстанавливается. Простой хеш пароля как ключ шифрования не используем.
- При создании хоста не настраиваются пробросы и теги. Поля: адрес, порт, пользователь, название (по умолчанию адрес), группа, приватный ключ (необязательно: без ключа сервер спросит пароль в консоли; решение 2026-10-25).
- Хосты группируются в группы; тегов нет.

## Дизайн

- Макеты (канвас Design): https://claude.ai/artifact/7cyxKFMe6YDkds18e7ZN4B. Все десять артбордов в одном стиле: Хосты, Новый хост, Сессия (терминал), Ключи, Новый ключ, Шифрование хранилища, Пробросы, Настройки, Первый запуск, Ошибка подключения.
- Открытый вопрос (2026-10-24): перенести из пробного канваса четыре приёма Windows 11 — нейтральные серые (#202020 / #1B1B1B / #2D2D2D вместо синеватых), системный акцент #4CC2FF, нижняя акцентная линия у поля при фокусе, вкладки сессий минимум 160 px с крестиком. Делать одним проходом по всем экранам.
- Вкладка-«дом» в заголовке окна подписана именем текущего раздела (Хосты, Ключи, …), вкладки справа от неё — открытые сессии.
- Тёмная тема. Фон `#1a1d22`, заголовок окна и строка состояния `#121417`, боковая панель `#16181d`, карточки `#22262d`, фон терминала `#0f1114`, рамки `#2a2f37`, текст `#e8eaed`, приглушённый текст `#a3acb8`, акцент `#4f8ff7`, статус «подключено» `#3fb950`.
- Шрифты: в макетах Inter + JetBrains Mono; в приложении интерфейсный шрифт заменить на системный Segoe UI Variable, моноширинный оставить JetBrains Mono (или Cascadia Mono).
- Радиусы 4 px у контролов, 6–8 px у карточек и диалогов. Без градиентов, эмодзи и цветных полос слева у карточек.
- Вкладки сессий живут в заголовке окна (как в Windows Terminal), слева от кнопок свернуть/развернуть/закрыть.

## Поставка (решено 2026-10-25)

- Программа распространяется через лаунчер Stash (`wepmaner/stash`): портативная папка файлов, без установщика и прав администратора. NSIS не используется.
- Репозиторий публичный: в коде, тестах, документах и `go.mod` не должно быть локальных путей, адресов серверов, личных данных и ключей, кроме фикстур `internal/keys/testdata` с описанным происхождением.
- Все данные программы в `%APPDATA%\sshclient\` (хранилище `vault.json`, `known_hosts`, состояние окна, кэш WebView2 в подпапке `WebView2`). Рядом с exe ничего не создаётся: Stash сверяет файлы пакета с эталоном и «чинит» изменённые. Имя папки данных совпадает с именем exe `sshclient.exe`.
- Сборка: `wails3 build` (Taskfile в корне и `build/`, только Windows) кладёт exe в `build/bin/sshclient.exe`; `wails3 dev` — режим разработки. В `build/` только `config.yml`, `Taskfile.yml`, `appicon.png` и `windows/` (иконка, манифест, `info.json`): лишние шаблоны вроде `build/ios` ломают `go build ./...`.
- Версия задаётся CI из тега: `wails3 build VERSION=X.Y.Z` передаёт `-X main.version` (`build/windows/Taskfile.yml`); в коде `var version = "dev"`; показывается в Настройках.
- Выпуск: аннотированный тег `vX.Y.Z` с текстом «Что нового» → GitHub Actions собирает, упаковывает `stash-pack` и публикует релиз → Stash у пользователей предлагает обновление. Манифест `stash.json` в корне, id `ssh-client` не меняется.

## Правила нативного поведения

- Старт без сплэш-экрана, окно открывается на прежнем месте и размере.
- Наведение на «Развернуть» показывает системные раскладки Snap; двойной щелчок по заголовку разворачивает окно; Alt+Space открывает системное меню.
- Системные диалоги выбора файлов и уведомления Windows. Контекстные меню собственные (`ui/Menu.svelte`): правый щелчок по хосту, группе, ключу и пробросу открывает то же меню, что кнопка «Ещё», в точке курсора (решение владельца 2026-10-25 после пробы системных меню Wails v3).
- Никаких спиннеров на локальных действиях; поиск по хостам мгновенный.
- Движение короткое: диалог 150 мс с масштабом от 0,97, подсветка наведения 80 мс, переключение вкладок без анимации; уважать системную настройку «уменьшить движение».
- Терминал: нажатие клавиши отображается в том же кадре; Ctrl+Shift+C / Ctrl+Shift+V, правый щелчок вставляет, как в Windows Terminal.
